# 空间改造运营工作台历史设计

> 历史材料，以当前代码、测试和最新报告为准。

## 设计目标

把空间改造视为运营后台中的决策工作台，而不是面向公众的独立展示页。工作台需要用图示表达节点、关系、状态和风险，并允许运营人员进入详情核对依据。

## 当时确认的方向

- 后台承担空间改造的主要查看与操作入口。
- 总览图只展示决策所需摘要，详情页承载证据和操作。
- 图示颜色、连线和标签必须具有稳定语义，不能只作装饰。
- 加载、空态、权限不足和上游失败应有明确反馈。
- 删除公开入口不能破坏其他业务路由或数据访问边界。

## 数据与安全边界

- 浏览器不接触管理员 token。
- 工作台只展示角色允许的数据。
- 写操作必须由现有会话、BFF 和服务端校验保护。

## 当前验收方式

当前布局、路由、数据流和错误处理以 `apps/admin`、`apps/web` 的代码与测试为准；本文只保留设计背景。
