# 管理后台访客访问设计

## 目标

将 `admin.zoumavillage.xyz` 调整为无需登录即可浏览，同时保留现有管理员登录入口。匿名访客可以读取全部后台数据，并可使用经明确批准的 AI、内容生成、空间诊断和设施决策生成能力；其他会修改业务状态的操作仍须通过管理员 HttpOnly 会话鉴权。

## 已确认范围

- 匿名访客可以访问全部后台页面和全部现有读取接口。
- 匿名访问不屏蔽村民、采收物流、反馈等可能包含个人信息的模块或原始响应。
- `/login` 继续提供管理员口令登录。
- 登录管理员保留现有完整操作权限。
- 不修改 Prisma Schema、迁移、Web API 的 `X-Admin-Token` 鉴权或包级导出。
- 浏览器不得接触 `ADMIN_API_TOKEN`、`ADMIN_LOGIN_PASSWORD` 或 `ADMIN_SESSION_SECRET`。

## 权限模型

### 匿名访客

匿名访客可执行：

- 所有 `GET` 和 `HEAD` 请求；
- `POST /knowledge/query`；
- `POST /ai/query`；
- `POST /ai/generate-content`；
- `POST /renovation/run-weekly`；
- `POST /infrastructure/decide`。

以上路径均指 Admin BFF 的 `/api/admin` 后缀。例如浏览器请求 `/api/admin/ai/query` 时，权限判断使用 `/ai/query`。

匿名访客不得执行其他 `POST`、`PUT`、`PATCH` 或 `DELETE` 请求。白名单按请求方法和规范化完整路径精确匹配，不接受模糊前缀、子路径或仅凭客户端状态放行。

### 登录管理员

持有有效 `zouma_admin_session` HttpOnly cookie 的管理员继续拥有现有完整权限。会话签名、有效期、登录限流、SameSite、Secure 和 HttpOnly 配置保持不变。

## 服务端架构

### 页面中间件

`apps/admin/src/middleware.ts` 不再把匿名页面请求重定向到 `/login`。`/` 仍由现有页面跳转到 `/dashboard`，`/login` 继续可直接访问。

中间件与 BFF 使用同一权限判断规则：

- 匿名页面、`GET`、`HEAD` 和五个访客能力请求可继续处理；
- 其他匿名写请求返回 `401`；
- 登录管理员请求继续处理。

中间件提供提前拒绝，BFF 是最终权限边界。即使请求绕过中间件或直接调用 Route Handler，BFF 也必须独立执行权限判断。

### 管理端 BFF

`apps/admin/src/lib/admin-bff.server.ts` 在代理前完成以下检查：

1. 判断请求是否属于匿名允许范围。
2. 不属于匿名允许范围时验证管理员会话。
3. 对所有非 `GET/HEAD` 请求保留同源 `Origin` 检查；跨域写请求返回 `403`。
4. 验证 `WEB_API_BASE` 和 `ADMIN_API_TOKEN` 已配置。
5. 删除浏览器 cookie、Host 和传输相关请求头，由服务端写入可信 `X-Admin-Token`。
6. 继续过滤上游 `set-cookie`、压缩和传输响应头。

匿名访客获得的读取和访客能力请求仍通过服务端 BFF 访问 Web API，浏览器源码、请求和响应中不出现服务令牌。

## 界面状态

根布局在服务端读取并验证管理员会话，只向客户端传递布尔值 `canWrite`。客户端访问权限上下文以该值驱动界面状态，不传递 cookie、签名或密钥。

侧边栏显示当前访问状态：

- 匿名用户显示“访客模式”和“管理员登录”入口；
- 已登录用户显示“管理员模式”。

访客模式继续允许导航、读取、搜索、筛选、排序、翻页、刷新、选择记录和查看详情。以下访客能力保持可用：

- 知识问答和运营问答；
- 内容生成；
- 空间改造周度诊断；
- 设施决策建议生成。

其他写操作控件在访客模式下禁用，并显示“登录管理员后可操作”的提示，包括新增、编辑、保存、删除、归档、审批、拒绝、确认、状态流转、文件上传、人工升级、手工传感器录入、设备指令批准或执行、模拟创建、复制、运行和复盘保存。

界面权限只改善使用体验，不作为安全边界。服务端始终重新判断请求权限。

## 数据与副作用

- AI 问答和内容生成可能调用外部模型并产生调用费用。
- 空间改造周度诊断可能创建或更新改造策略。
- 设施决策建议生成可能创建待审批的控制指令，但匿名访客不能批准、拒绝或标记执行指令。
- 现有 Web API 频率限制继续生效，不提高匿名额度。
- 按已确认范围，匿名读取可能向浏览器返回现有接口中的个人信息；本次不增加脱敏或模块屏蔽。

## 错误处理

- 匿名调用非白名单写请求时返回 `401`，界面提示需要管理员登录。
- 跨域写请求返回 `403`。
- BFF 配置缺失时继续返回 `503`。
- Web API 频率限制继续返回 `429` 和现有重试信息。
- 管理员会话在页面打开期间过期时，后续受保护操作由服务端拒绝，界面提示重新登录，不显示虚假的成功状态。
- 上游错误、降级响应和现有页面加载失败提示保持原有语义。

## 测试策略

采用测试驱动开发，先更新或新增失败测试，再修改实现。

服务端测试覆盖：

- 匿名打开后台页面不再跳转 `/login`；
- 匿名 `GET/HEAD` 请求可由 BFF 代理；
- 五个精确白名单 `POST` 可由匿名访客代理；
- 相似但不完全匹配的路径不可匿名调用；
- 其他匿名 `POST/PUT/PATCH/DELETE` 在调用 Web API 前返回 `401`；
- 登录管理员仍可执行受保护写请求；
- 跨域访客能力和管理员写请求仍返回 `403`；
- BFF 继续覆盖攻击者提供的 `X-Admin-Token`，且不向上游转发浏览器 cookie；
- 浏览器生产源码不包含服务令牌。

界面测试覆盖：

- 根布局向 Admin Shell 传递正确的 `canWrite`；
- 访客模式标识和管理员登录入口存在；
- 五类访客能力在匿名状态下可用；
- 代表性的保存、审批、上传、执行和模拟写入控件在匿名状态下禁用；
- 管理员状态下受保护控件恢复可用。

交付前运行仓库完整门禁：

```bash
pnpm type-check
pnpm test
pnpm docs:check
pnpm build
git diff --check
```

由于访客模式会调整模拟工作台的写操作控件，还需运行模拟相关检查：

```bash
pnpm --filter @zouma/simulation test
pnpm simulation:run --seed 20260713 --scenario NORMAL
```

## 验收标准

- 未携带管理员 cookie 访问 `/`、`/dashboard` 或任意后台页面时能够直接浏览，不被重定向到 `/login`。
- 匿名访客能够读取所有现有后台数据，并能使用五个已批准的 `POST` 能力。
- 匿名访客无法通过界面或直接请求执行未批准的写操作。
- 管理员可从 `/login` 登录，登录后继续使用全部现有写操作。
- `ADMIN_API_TOKEN` 始终只存在于 Admin 服务端。
- 所有相关测试和仓库完整门禁通过。
