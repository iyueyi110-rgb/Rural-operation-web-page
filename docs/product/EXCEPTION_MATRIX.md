# 认养履约异常矩阵

本矩阵用于面试说明产品如何处理异常。已实现的行为以代码和测试为准；仅有设计方案的场景明确标注，不把设计方案描述成上线能力。

| 异常触发 | 用户影响 | 当前系统行为 | 人工门禁 | 需要观察的指标 |
| --- | --- | --- | --- | --- |
| 村民未在响应窗口内接单 | 养护任务可能无人执行 | 记录超时并进入重新分配或升级路径；模拟中限制候选次数 | 运营确认高风险重派 | 接单率、重派率、平均接单时间 |
| 村民拒单或任务无法执行 | 任务无法按原计划推进 | 支持拒绝、重新分配和异常上报动作 | 运营确认任务替代方案 | 异常闭环时效、人工介入次数 |
| 凭证少于两张或材料不完整 | 用户看不到可信养护记录 | 阻止提交或由运营退回；村民创建新的凭证版本后重新提交 | 运营审核通过或退回并填写原因 | 首次审核通过率、退回率、重提次数 |
| 审核队列积压 | 权益兑现和结算延迟 | 按审核队列和准备时间调度；逾期进入运营关注范围 | 运营调整审核容量和优先级 | 平均审核时长、最终审核通过率 |
| 连续降雨影响现场作业 | 原定截止时间不再可执行 | 在启用天气规则且窗口相交时延长有效截止时间，并生成排水/复核任务 | 运营确认用户通知和现场安排 | 按时提交率、延期任务数、异常闭环时效 |
| 收获权益延迟或未完成 | 用户无法按约获得权益 | 权益仍进入应履约分母；认养不会被错误标记为完成 | 运营处理替代权益、延期或退款工单 | 权益按时兑现率、投诉率、退款处理时效 |
| 树木减产、死亡或不可继续认养 | 原认养承诺可能无法完全兑现 | 当前只保留人工处理设计，不宣称系统自动判责或自动赔付 | 运营人工确认责任、替代树和权益方案 | 退款率、替代履约率、人工处理时长 |
| 用户发起退款 | 订单和权益进入争议处理 | 创建退款工单，当前不执行真实退款 | 必须人工审核，不授权 Agent 直接退款 | 退款处理时效、重复投诉率 |
| Agent 无模型密钥或建议失败 | 无法生成智能风险建议 | 以 `MODEL_UNAVAILABLE` 结束，不创建 Recommendation；人工流程继续 | 不影响人工审核和结算门禁 | Agent 可用率、人工介入次数 |

## 核心状态约束

- 认养任务使用动作式状态：`accept`、`start`、`submit_evidence`、`resubmit`、`report_exception`、`approve`、`reject`、`settle`、`mark_overdue`。
- 凭证采用不可覆盖版本；退回后必须创建新的提交版本。
- 结算只能基于已审核任务，退款、判责、结算和状态修改不授权给 Agent。
- 观察窗口内未到约定时间的权益不提前计入逾期；已到约定时间但未履约的权益仍计入履约分母。
