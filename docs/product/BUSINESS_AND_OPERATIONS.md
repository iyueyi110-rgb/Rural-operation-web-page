# 商业与运营模型

本页用于回答认养方案如何定价、履约成本由谁承担以及各参与方如何协作。当前金额均为 Demo 中的产品假设或规则样本，尚未经过真实支付和试点验证，不代表已上线价格、收入或利润。

## 方案与承诺

| 方案     | Demo 定价 | 当前页面表达                                                   | 试点前必须锁定                                           |
| -------- | --------: | -------------------------------------------------------------- | -------------------------------------------------------- |
| 一季认养 |    399 元 | 阶段性成长记录、一次收获权益、电子证书，以及到村采摘或配送入口 | 收获额度、记录频次、配送范围、替代权益和退款条件         |
| 全年认养 |    999 元 | 全年节气提醒、养护更新、活动优先权、电子证书和约定的收获权益   | 全年任务清单、权益次数、活动容量、续养规则和极端天气处理 |

用户购买的是持续可查看的养护过程和约定权益，不是树木所有权。页面中的“最低产量保障、实地采摘、树牌和冷链配送”仍需在真实协议中明确额度、时间和适用条件。

## 收入与成本关系

```text
认养收入
  → 村民已审核任务收益
  → 日常养护与果园协作成本
  → 运营审核、客服和异常处理成本
  → 采摘、包装、配送或替代权益成本
  → 支付通道、系统和基础服务成本
  → 风险准备与可分配结余
```

当前黄金案例中的首月养护任务使用 48 元演示收益。该金额只证明系统能记录任务收益和结算门禁，不是村民真实收入标准。试点应按任务类型、预计工时、技能要求、距离和紧急程度建立任务价目，并检查同类任务的收益差异。

## 三方职责

| 参与方               | 主要投入                                               | 收益关系                                                   | 当前边界                                   |
| -------------------- | ------------------------------------------------------ | ---------------------------------------------------------- | ------------------------------------------ |
| 村集体或果园运营主体 | 树木和场地协调、认养协议、线下履约资源、食品与现场安全 | 认养收入的业务承接主体；真实分配方式需由合同和财务制度确定 | Demo 不预设分账比例                        |
| 村民履约人员         | 养护、拍照、采摘、包装或现场协作                       | 凭证审核通过后形成任务结算资格                             | 当前只有演示收益和结算状态，不发生真实转账 |
| 平台与运营人员       | 产品系统、派单审核、客服、异常处理和数据记录           | 真实试点可按技术服务或运营服务核算，比例需另行审批         | 当前不宣称平台收入或盈利                   |

## 责任边界

| 情况                   | 默认处理                       | 人工决策                                               |
| ---------------------- | ------------------------------ | ------------------------------------------------------ |
| 连续降雨或不可抗天气   | 保留原因并调整任务截止时间     | 运营确认最终延期和用户通知                             |
| 减产但仍可履约         | 优先提供约定额度或等值替代权益 | 运营确认替代品、时间和差额                             |
| 树木死亡或无法继续认养 | 暂停相关任务与结算             | 运营与业务主体确认替代树、补偿或退款工单               |
| 凭证造假               | 暂停任务和结算，保留原始版本   | 人工复核责任，不由系统自动判责                         |
| 采摘或配送延迟         | 提示异常并记录新的预计时间     | 用户选择等待、替代权益或退款审核                       |
| 用户主动取消           | 创建退款审核工单               | 根据协议、已发生履约成本和责任归属处理；当前不自动退款 |

## 单位模型验证

真实试点需要对每一笔认养记录以下口径：

`单笔贡献结余 = 实收认养款 - 村民任务收益 - 养护成本 - 审核客服成本 - 采摘包装配送成本 - 异常与退款成本 - 支付及系统变动成本`

当前没有真实实收、成本和退款数据，因此不能宣称 399 元或 999 元方案盈利。首轮试点的目标是得到成本结构和责任分布，而不是提前证明商业模式成立。

## 续养触发

首次权益兑现后 7 天内收集成长记录查看、权益使用和续养意向。只有用户已看到完整履约证据、异常已关闭且下一周期权益明确时，才发起续养询问；不以频繁通知替代真实价值。

## 试点需要回答的问题

1. 两种方案的承诺是否能被用户准确理解，哪一项权益真正影响选择？
2. 每类任务的实际工时、退回率和合理收益是多少？
3. 审核、客服、采摘和配送分别占单笔成本多少？
4. 减产、延期和退款由谁决策，用户可接受的替代权益是什么？
5. 在保障村民收益公平和到期权益按时兑现后，单笔贡献结余是否仍可持续？
