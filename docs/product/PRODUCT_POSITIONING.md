# 产品定位

## 登记类型

`product`

## 用户

当前 MVP 服务三类业务用户：

- **认养用户**：购买一年期认养方案，查看树木成长记录并获得约定权益。
- **村民履约人员**：接收养护任务、执行任务、提交凭证并响应退回或异常。
- **运营人员**：分配任务、审核凭证、处理异常、确认权益和结算门禁。

项目评审与汇报查看者是作品集的阅读对象，不属于产品用户；游客、住宿、研学和门票用户属于后续扩展场景。

## 产品目标

围绕 `LZ-018` 跑通“选树、认养、养护、凭证、审核、权益、续养/退款”的可追踪履约闭环：用户看见服务是否兑现，村民知道任务和收益，运营人员可以在异常发生时及时介入。

## MVP 范围

当前只以认养履约为主线，核心流程为：

`选树 → 认养下单 → 生成任务 → 村民接单 → 上传凭证 → 运营审核 → 权益兑现 → 续养/退款申请`

门票、住宿、研学、空间改造、IoT、数字人、3D/AR、社区和 UGC 均保留为后续能力，不作为当前产品价值的证明。

## 结果边界

- 当前支付入口为演示能力，不发生真实扣款。
- 退款创建人工审核工单，不执行真实退款。
- Agent 处于只读影子模式，不直接修改订单、退款、结算或履约状态。
- 规则模拟数据用于发现规则风险，不代表真实用户、村民或运营结果。

## 品牌性格

克制、空间化、可信。前台结合建筑竞赛展板与成熟数字产品，后台保持稳定的运营控制台气质。整体低饱和、有层次、有乡村真实感，不使用赛博朋克、过度霓虹或模板化 AI 渐变。

## 反向参考

不做普通乡村旅游门户、炫技型 AI SaaS 首屏、蓝紫霓虹控制台、堆满相同卡片的模板页或只有口号没有运营逻辑的展示站。不能牺牲现有路由、业务数据和可操作流程来换取纯视觉效果。

## 设计原则

1. 一棵树带动全村运营：每个首页模块都应回到认养关系、村民任务、运营决策或空间更新。
2. 空间先于装饰：视觉层次来自地形、路径、节点、院落和数据关系。
3. 前台展示有张力，后台操作要安静：两端共享颜色和组件气质，但密度与动效分开处理。
4. 真实资产优先：优先复用走马村现有图片与地图素材，抽象图形只用于解释系统关系。
5. 轻平台可被信任：保留清晰入口、状态、空态和错误反馈。

## 无障碍与包容性

默认遵循 WCAG AA。前台动效必须支持 reduced motion；移动端优先保证清晰、可读、可点击。后台控件需有明确的 hover、focus、disabled 和 loading 状态，避免只靠颜色表达状态。
